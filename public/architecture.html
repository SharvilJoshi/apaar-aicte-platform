Reference Architecture · v1.0

APAAR-based Student Data Management
& Verification System

A layered, service-oriented architecture that turns heterogeneous institutional submissions into a single APAAR-keyed national student repository. Every request passes through an authentication edge, a validation pipeline and an immutable audit sink; every published record carries an issuer-signed credential that third parties can verify without trusting the transport.

3 · Security, Privacy & Governance Model

🔑

Authentication

Session tokens (48-hex, 8-hour TTL) issued on credential check; server-side session store supports immediate revocation on logout.

  • POST /api/auth/login · logout
  • Token via auth_token / X-Auth-Token header
  • 401 on expiry → forced re-login
🛡

Authorization (RBAC)

Every route declares allowed roles; institution callers are additionally row-scoped to their institution_id.

  • AICTE_ADMIN — national scope
  • INSTITUTION — own records only
  • VERIFIER — academic PII only
  • public — format check only, zero PII
✒️

Verifiable Credentials

Each verified record is wrapped in a W3C-style credential and signed with HMAC-SHA256 over the canonical JSON.

  • proofValue = HMAC(canonical)
  • Re-verified on every read
  • Issuer DID + key id in proof
  • Copyable to external wallets
🔒

Privacy & Consent

Data-subject consent is captured at upload time and can be revoked later; verifiers never see contact or demographic extras.

  • Consent scope + timestamp stored
  • Verifier view = academic fields only
  • Public check returns no PII
⟲

Audit Trail

Append-only log; each event carries actor, role, action, human-readable detail, scope and UTC timestamp.

  • LOGIN · STUDENT_CREATE/UPDATE
  • BULK_UPLOAD · VERIFY · CONSENT_UPDATE
  • REPORT_EXPORT · scoped per role
⚠

Integrity Controls

Errors block commits by default; overrides are explicit, deliberate and recorded — never silent.

  • 422 with per-rule findings
  • force=true → audited override
  • 10-rule registry, code-tagged

4 · Deployment & Scale-out Path

Demo deployment (this build) Ruby WEBrick API + JSON document store + static SPA — zero external dependencies, single process, runs anywhere.
Production deployment API tier behind L7 load balancer → stateless app containers → PostgreSQL (student master, row-level security by institution) + Redis sessions + S3 audit archive.
Scale & interoperability Horizontal API replicas; async bulk-ingest queue with per-batch validation workers; OpenAPI 3 spec for institutional ERP integration; webhook callbacks for verification events.
Production hardening checklist Argon2id password hashing · mTLS for institution API keys · rate limiting per key · field-level encryption for PII at rest · daily signed snapshots for offline verification · OWASP ASVS L2 review · DPDP Act consent workflows.
Observability Structured JSON logs with trace id · RED metrics per endpoint · anomaly-rate SLO (alerts on rule-count spikes) · audit-log completeness monitor · nightly APAAR integrity sweep.
